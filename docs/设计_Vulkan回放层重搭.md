# 设计：Vulkan 回放层重搭（安卓 / 鸿蒙共用）

> 11-11 起草。本文定分层、目录、里程碑和鸿蒙接入口；逐命令的接线表在 `docs/直连_Vulkan回放接线表.tsv`（随 M0 入库）。
> 与 [设计_回放核心共用.md](设计_回放核心共用.md) 的关系：沿用它的分层和 `nvn_gpu_*` 契约（`graphics/nvn/gfx/nvn/nvn_backend.h` v2），只改施工顺序，见 §3。
> 与 [架构_多终端.md](架构_多终端.md) 的关系：落实其中「渲染按图形 API 分后端，Vulkan：安卓 / 鸿蒙」这一条。

## 0. 结论

1. 安卓现有回放层（`android/native/nvn` 的 `mtl_vk_shim.c` / `nvn_vk_first_draw.c` / `nvn_vk_texcache.c` 等，`android/native/direct` 的 `vk_record.c` 等）整体退役，不在上面继续修。
2. 新层分三块，每块只做一件事：
   - **回放核心**：实现前端调用的 `nvn_be_*`，只说 NVN 语义，纯 C，不 include 任何图形 API 头和平台头。结构逐段对齐 iOS 的 `nvn_mtl.m`，能逐函数对照。
   - **Vulkan 后端**：实现 `nvn_gpu_*`，只用 Vulkan 核心接口和能力查询。以现有的 `android/native/nvn/backend_vulkan.c`（已有契约用例在 lavapipe + 校验层上跑）为底补完。
   - **平台件**：窗口与上屏表面、显示节拍、内存池后备、日志、路径、线程优先级。经一个薄接口 `nvn_plat.h` 注入。安卓一份实现，鸿蒙一份实现。
3. 回放核心和 Vulkan 后端放共用目录，安卓和鸿蒙链同一份源码。鸿蒙接入 = 写一份平台件 + 出包目标，不改核心和后端。
4. iOS / macOS 不动：`nvn_mtl.m` 继续是苹果端的回放层，本次一行不改。
5. 不与旧层做对照验收。验收口径是绝对的：命令接齐、画面正确、帧率到上限、内存不涨（§5）。

## 1. 分层

```
共用底层   runtime/（装载、线程、改写器）  services/（系统服务）  translator/（着色器翻译）
前端       graphics/nvn/gfx/nvn/hle_nvn.c（NVN 调用 → 录制命令流）
             │ nvn_be_*（上沿，约 66 个函数）
             ▼
回放层     苹果：nvn_mtl.m（回放 + Metal 调用在一个文件里，现状保留）
           安卓 / 鸿蒙：
             回放核心  graphics/nvn/replay/      命令解码、状态与脏位、池与别名、贴图身份与按需建图、
                                                  着色器变体选择、通道规划、提交与完成、上屏队列与节拍策略
               │ nvn_gpu_*（下沿，nvn_backend.h）        │ nvn_plat_*（nvn_plat.h）
               ▼                                          ▼
             Vulkan 后端  graphics/nvn/gpu_vk/          平台件  android/native/gfx_plat/ │ 鸿蒙：由鸿蒙组提供
               设备与能力、缓冲、贴图、管线、通道、        窗口 → VkSurfaceKHR、显示节拍、内存池后备、
               布局跟踪与屏障、延迟销毁、交换链            日志、目录、线程优先级
```

判定一段代码归哪一块：换一个图形 API 还要原样存在的，进核心；只有 Vulkan 才需要的，进后端；换一个操作系统就要重写的，进平台件。

三条硬规矩（门禁用 include 扫描守）：
- 回放核心不 include `vulkan/*`、`android/*`、`jni.h`，也不 include 平台件的私有头。
- Vulkan 后端不 include `android/*`、`jni.h`；不读系统属性；不按厂商号、设备号、驱动版本分支，只按 `vkGetPhysicalDeviceFeatures*` / 格式属性 / 扩展列表的查询结果分支。
- 平台件不解码命令、不持有 NVN 状态。

## 2. 平台接口 `nvn_plat.h`

只放「换操作系统就要重写」的东西。草案（M0 随骨架定稿，鸿蒙组审）：

| 组 | 接口 | 安卓实现 | 鸿蒙对应物 |
|---|---|---|---|
| 实例扩展 | `nvn_plat_instance_exts`：建实例要加的表面扩展名 | `VK_KHR_android_surface` | `VK_OHOS_surface` |
| 表面 | `nvn_plat_surface_create(instance, 窗口句柄)` → `VkSurfaceKHR`；`nvn_plat_window_size` | `ANativeWindow` | `OHNativeWindow` |
| 窗口租约 | 窗口给出 / 收回的通知（进后台、旋转） | 现有 `wsi_lease` | XComponent 生命周期 |
| 显示节拍 | `nvn_vsync_start` / `nvn_vsync_stop`（已有 `nvn_vsync.h`） | AChoreographer | `OH_NativeVSync` |
| 内存池后备 | `nvn_plat_pool_backing`：给一块游戏内存要一个 GPU 可直接用的后备；不支持就返回「没有」，核心走上传路径 | AHardwareBuffer 池 | 鸿蒙自定；可先返回「没有」 |
| 日志 | `nvn_plat_log(级别, 类别, 文本)` | logcat | hilog |
| 目录 | 缓存目录、诊断目录 | 应用私有目录 | 应用沙箱目录 |
| 线程 | 线程命名、优先级提示 | bionic | musl |
| 开关 | `nvn_plat_flag(名字, 缺省)`：调试开关的唯一入口 | `debug.s2a.*` 系统属性 | 鸿蒙参数 |

头文件现状（`graphics/nvn/replay/`）：`nvn_plat.h` v1 已有日志、开关、目录三组；`nvn_plat_vk.h` 已有实例扩展、表面、窗口尺寸三个入口（只有 Vulkan 后端 include）；显示节拍沿用 `nvn_vsync.h`。窗口租约、内存池后备、线程三组在接到对应功能时加，加之前先在本文定形状。安卓实现在 `android/native/gfx_plat/`。

写跟踪（靠缺页信号发现 CPU 写了哪些页）不在图形层：共用的 `nvn_dirty` + `platform/plat.h` 的信号接口已经是单点，图形层只读「这些页脏没脏」。musl 与 bionic 的差异在 `platform/` 那一份里解决。

## 3. 施工顺序（相对原设计的改动）

原设计的顺序是「先把 iOS 的 `nvn_mtl.m` 抽成核心 + Metal 后端（D2–D7），再接 Vulkan（D8）」。这要先动稳定的苹果端，而且至今没开工。

现在改成：**核心直接在 Vulkan 上新写，安卓做第一个用户**。
- 苹果端继续跑 `nvn_mtl.m`，零风险。
- 核心照 `nvn_mtl.m` 的结构和语义写，但只带语义，不带 Metal 的变通。
- 核心在安卓 / 鸿蒙上达到验收口径以后，再评估苹果端是否换到「核心 + Metal 后端」。到那时核心已经被两个平台的真机验证过，换轨是一次有基准的替换，不是边抽边猜。

M1 之后补上的三项（11-11，契约升到 v4）：带裁剪的清除（契约新增通道内按矩形清 `nvn_gpu_clear_rect`，后端用 `vkCmdClearAttachments`；契约用例 C74）、深度偏移（开关进管线，factor / units / clamp 走动态状态；C75）、计数器报告（时间戳类与管线统计类在段完成后写回）。这三项里还没接的：只写部分颜色通道 / 部分模板位的清除（矩形清不看写掩码，不拿它近似）、遮挡计数、点 / 线填充模式、按报告所在位置给 GPU 时间（现在同一段的多条报告拿到同一个完成时刻）。真机上还没验这三项。

## 6. 对鸿蒙组七条需求的落点

| 需求 | 落点 |
|---|---|
| 1 平台层收成薄接口 | §2 的 `nvn_plat.h`，M0 定稿；核心与后端的 include 规矩由门禁守（§1）。出包链 `--target ohos` 的位置随平台件一起留 |
| 2 Metal 隐式行为显式化 | 全部落在 Vulkan 后端一处：每个子资源的布局 / 阶段 / 访问跟踪与屏障（契约定稿 #7）；release 后推迟到最后一次使用结束再销毁（契约 A3），回收点在后端的完成线程里，核心和平台件都不需要调用它，所以漏不掉；清除并进 `loadOp`（核心的通道规划给出 load / store，后端照做）；读回与拷贝走显式 fence |
| 3 不按厂商分支 | §1 第二条硬规矩。`nvn_gpu_caps` / `nvn_gpu_format_caps` 是核心拿能力的唯一来源；纯深度格式的区域拷贝按 DEPTH aspect 做，进契约用例 |
| 4 不依赖安卓 C 库专有行为 | 核心与后端只用 C11 + pthread；写跟踪不在图形层（§2 末段）。「读时回写」不做全局开关 |
| 5 着色器身份 | 身份只由内容决定这条沿用现有编译链的内容摘要。本轮（M0–M2）不改身份字段；M2 之后单开一项处理「同一份编译结果对应多个身份」和离线库格式版本号。请鸿蒙组先给身份字段的跨局变化统计 |
| 6 draw 热路径预算与计时 | 核心的绘制状态按脏位更新，不整块拷贝；描述符集按内容复用。后端和核心各有分段计时，经 `nvn_gpu_stats` 一个出口读。预算数字在 M1 量出首个读数后写进本文 |
| 7 「未接 / 不支持」可统计 | 一个出口 `nvn_unimpl(类别, 名字, 调用点)`：按（类别，名字）计数，首次出现打一行日志，收局时出汇总表，普查工具读这张表。核心里没接的命令、后端返回的 `NVN_GPU_E_UNSUPPORTED` 都走它 |

鸿蒙组问的三件事：
1. 平台接口这次一并定，M0 交付里就有。鸿蒙组按接口写实现提 PR。
2. 着色器身份规则本轮不动，M2 之后单开；统计现在就可以给。
3. 最小实践：2D 用 0100633007D48000 的标题画面，3D 用 0100DCA0064A6000 起局到可操作画面。

## 7. 没定的事

- `vk_device.c` 现在由安卓的会话装配点调用建设备；搬进共用目录后「谁建实例、谁选物理设备」的接口形状，M0 定。
- （已定）内存池在后端有一份等大镜像，按页同步，同步点就是使用点；游戏内存是唯一真值。零拷贝后备作为后端的可选能力以后再加，核心不用改。
- 显示节拍在安卓默认开不开：M1 在 120 Hz 屏上不开节拍量到稳定 60 帧、丢 0；帧间隔的均匀程度没量，M2 量过再定。
